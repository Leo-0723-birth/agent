# 正样本率提升方案

> 问题：当前训练集正样本率极低（30d **2.53%** / 60d **5.79%** / 90d **8.16%**），
> 导致 F1 等分类指标难达标（赛题要求 F1≥0.65）。正样本率低有三个根因：
> **标签口径窄、采样粒度粗、事件窗口浪费**。以下方案按"见效快 → 见效大"排序。

---

## 一、数据侧（根治，优先做）

### 1. 采样粒度：报告期 → 月度快照（最关键）
当前每个 (公司, 报告期) 一个样本（一年 4 期）。改成**每月一个快照 T**：
- 同一公司一年 12 个样本（从 4 → 12）；
- **窗口重叠**：一次问询事件落在 (T, T+60] 会使其**前 2-3 个月的快照都为正样本**，
  正样本量约 ×3；
- 实现：对每个公司从起始日到结束日每月生成 T，财务特征取"披露日 ≤ T 的最新一期"。

### 2. 标签口径扩展（三选一，可叠加）
| 方案 | 标签定义 | 效果 |
|------|---------|------|
| A（现状） | 60 天内收到**年报问询函** | 正样本最少（~2-5%） |
| B | 60 天内收到**任意问询类函**（年报/半年报/季报/重组/许可/关注函） | 正样本 ×2-3（当前事件 4785 封中 annual_report 仅 1925） |
| C（推荐进阶） | **多标签**：`target_annual`（年报问询）+ `target_attention`（关注函）分开建模 | 两个任务各自建模，关注函不再是噪声 |

> 本次数据已用 kind=='letter' 的全部问询函（含 attention/restructuring 等），
> 正样本率即方案 B 口径；若要更纯，可再按 type 细分或做多标签。

### 3. 预测窗口：60 → 90 天
90d 正样本率 8.16% ≈ 60d 的 1.4 倍。赛题允许 30/60/90，主窗口可用 90d 或 60/90 双输出。

---

## 二、算法侧（模型能做的都做了，但治标）

| 手段 | 现状 | 说明 |
|------|------|------|
| SMOTE-NC | ✅ 已用 | 正样本≥5 时合成，目标占比≤15% |
| 类别权重 | ✅ 已用 | RF balanced / LGB scale_pos_weight / XGB ×5 |
| **Focal Loss** | ⏳ 可加 | 对"易分负样本"降权，专治极端不平衡（XGB objective 自定义） |
| 阈值选择 | ✅ 已用 | 验证集最大化 F1（不是 0.5） |
| **评估主指标换 Top-10% 召回** | ✅ 已用 | 扫雷业务的本质是"把最危险的前 10% 抓出来"，比 F1 更贴业务 |

---

## 三、特征侧（提升区分度 = 间接提升有效正样本）

1. **F1 已从 300 → 50 维**（Spearman 筛选，去掉低效维度干扰）；
2. 补**高区分度特征**：F6 问询历史（已被问过 → 再次被问概率高，f6_inquiry_count 应给更高权重）；
3. **事件驱动样本**：在每次"公告/事件日"采样，公告密集的公司天然样本多。

---

## 四、效果预估与组合建议

| 组合 | 预计 60d 正样本率 |
|------|------------------|
| 现状（季度采样+年报函） | ~2-5% |
| + 月度采样 | ~8-12% |
| + 任意问询函（方案B，已用） | ~6% → 12-18% |
| + 月度采样 + 方案B + 90d 主窗口 | **~15-25%** |

**推荐落地顺序**：
1. **月度采样**（根因 2，×3 正样本）；
2. 标签明确口径（方案 B 或 C 多标签）；
3. 主窗口 60/90 双输出；
4. 模型加 Focal Loss + 保持 Top-10% 召回为主指标。

> 注意：月度采样需保证**财务特征按披露日对齐**（披露日 ≤ T），否则引入时间泄漏——
> 这与扫雷系统里"特征锚定 T"的原则一致。
