# 上市公司监管问询扫雷预警系统网页展示设计

- 日期：2026-08-26
- 状态：待用户审阅
- 目标分支：`网页展示设计`
- 适用范围：`导航入口.py`、`主控agent.py` 及六个独立 Agent Streamlit 页面
- 设计依据：赛题说明、仓库现有功能与数据产物、已确认的视觉方案

## 1. 背景

项目已经完成公告研读、财务异常检测、预测建模、案例匹配、归因解释、报告生成和主控编排等核心能力。当前网页可以运行，但主要使用 Streamlit 默认组件纵向堆叠，难以在有限答辩时间内同时呈现业务结论、模型能力和可追溯证据。

赛题要求系统支持公司代码或公司列表输入，输出未来 30/60/90 天监管问询概率、风险标签、主要诱因、相似历史案例、原文证据、模型置信度和完整 Agent 推理链路。本次设计仅重构展示层，不改变现有算法结论、模型接口或数据口径。

## 2. 设计目标

1. 让评委在首次打开页面时无需等待即可看到完整、可信的离线样例。
2. 让管理层先看到结论与建议，让分析师能够继续下钻到模型和证据。
3. 用真实数据图表解释预测表现、风险诱因、相似案例和 Agent 执行过程。
4. 让每条风险判断都能追溯到公告原文、财务原始数据、历史问询案例或工具日志。
5. 保留七个 Agent 独立页面和单独运行能力，降低对现有项目结构的影响。
6. 在外部数据源缓慢、模型冷启动或单个 Agent 失败时仍保持页面完整可用。

## 3. 非目标

- 不重新训练模型或改变 RF、LightGBM、XGBoost 的预测逻辑。
- 不修改现有风险标签体系、特征口径或案例检索排序算法。
- 不虚构后端尚未提供的数据；缺失数据必须明确标记。
- 不在本阶段引入新的用户权限、数据库或部署平台。
- 不将本地 brainstorming mockup 文件提交到仓库。

## 4. 已确认的核心决策

### 4.1 用户与展示定位

产品主要服务证券分析师、合规风控人员和企业管理层，同时需要满足比赛评委快速理解成果的需求。整体侧重专业、可信和结论清晰，而不是单纯强调科技感。

### 4.2 导航结构

采用 A 型结构，保留当前按 Agent 能力划分的七页导航：

1. 主控 Agent
2. 公告研读 Agent
3. 财务异常 Agent
4. 预测建模 Agent
5. 案例匹配 Agent
6. 归因分析 Agent
7. 报告生成 Agent

默认页面仍为主控 Agent。页面名称保持技术模块可辨识性，页面内部标题和摘要使用投研、风控能够直接理解的业务语言。

### 4.3 视觉方向

采用 B 型“管理层决策简报”风格：

- 页面底色：象牙白或非常浅的暖灰。
- 主要文字：深灰蓝，不使用纯黑。
- 品牌与标题强调：克制酒红。
- 数据图表：浅雾蓝、青绿、柔金和珊瑚红。
- 大面积图形避免深海军蓝、暗酒红和土金。
- 颜色含义直接标注在对应图表下方，不设置需要来回对照的全局颜色规则框。

### 4.4 首次打开行为

主控首页默认加载仓库内置的 `000004.SZ` 离线预计算结果，直接显示完整报告。页面顶部必须展示：

- `离线演示快照` 状态标签；
- 数据截止日期；
- 模型版本；
- 快照生成时间；
- `重新运行分析` 操作入口。

评委可以立即浏览全部成果，也可以主动触发真实七 Agent Pipeline。

## 5. 信息架构

### 5.1 页面模板分类

| 页面模板 | 对应页面 | 主要阅读任务 |
| --- | --- | --- |
| 综合研判页 | 主控 Agent | 先看结论，再看图表、证据、Agent 链路和报告 |
| 证据分析页 | 公告研读、财务异常、案例匹配 | 查找问题、阅读证据、打开原文或原始数据 |
| 模型解释页 | 预测建模、归因分析 | 查看预测质量、概率、模型贡献和业务归因 |
| 报告阅读页 | 报告生成、主控历史报告 | 阅读、存档和下载完整报告 |

### 5.2 主控首页模块顺序

主控首页采用“结论 → 指标 → 图表 → 证据 → Agent → 来源 → 报告”的固定顺序：

1. **状态与执行摘要**：公司、窗口期、离线/实时状态、风险结论和建议。
2. **成果指标卡**：模型 AUC、Top 10% 召回、建模样本、建模特征、案例库规模和链路可追溯率。
3. **核心图表**：30/60/90 天问询概率、Top 风险贡献、Top-5 相似案例。
4. **关键证据与建议动作**：风险严重度、问题类型、证据摘要、建议复核动作。
5. **七 Agent 执行链路**：状态、耗时、输出摘要和错误信息。
6. **证据与来源索引**：公告原文、财务指标、历史案例和推理日志入口。
7. **历史报告与下载**：报告选择、预览、Markdown 和 JSON 下载。

## 6. 视觉设计系统

### 6.1 色彩

建议使用以下设计变量，实施时允许在保持语义和对比度的前提下微调：

| 角色 | 建议颜色 | 用途 |
| --- | --- | --- |
| 页面底色 | `#F3F0EB` | 页面外围、区块分隔 |
| 卡片底色 | `#FFFDFA` / `#FFFFFF` | 研报主体和数据卡片 |
| 正文文字 | `#314456` | 标题、数字和正文 |
| 次要文字 | `#71808D` | 注释、时间、来源元数据 |
| 品牌酒红 | `#8F1D2C` | 页面顶线、重要标题、证据链接 |
| 浅雾蓝 | `#6F9FD8` | 模型、概率、一般数据系列 |
| 青绿 | `#70B8AA` | 预测正确、可信、完成状态 |
| 柔金 | `#E2B964` | 需要关注或中间等级 |
| 珊瑚红 | `#E58C82` | 风险、异常和主要正向风险贡献 |
| 分隔线 | `#DFE5E8` | 卡片边框、表格和坐标网格 |

不得仅依赖颜色传达风险，必须同时显示文字等级、图例或图下注释。

### 6.2 字体与对齐

- 中文正文优先使用系统可用的无衬线中文字体。
- 报告标题可使用克制的衬线字体，数据和控件全部使用无衬线字体。
- 数据卡主数值统一使用等宽数字特性 `tabular-nums`。
- 指标卡采用固定三段式网格：标题行、主数值行、辅助说明行。
- 图标统一使用相同尺寸的线性图标容器，禁止使用基线不一致的字符图标。
- `204 维`等“数值 + 单位”组合必须共享同一数值行并按基线对齐。

### 6.3 卡片与间距

- 相邻指标卡必须等高、等宽，并保持一致内边距。
- 图表卡片必须设置最小宽度、内部绘图区和边界裁切，禁止曲线越出卡片。
- 证据卡片可以使用风险色左边线，但不得用整块深色背景承载长文本。
- 页面区块之间使用留白和细分隔线，不使用强烈发光或霓虹效果。

## 7. 核心组件设计

### 7.1 状态页头

显示页面名称、公司代码、数据状态、截止日期、模型版本和主要操作。状态至少包含：

- 离线演示快照；
- 缓存结果；
- 实时数据；
- 正在运行；
- 部分完成；
- 运行失败。

### 7.2 成果指标卡

默认展示以下六项仓库真实成果：

- 60 天模型 AUC：`0.8335`；
- Top 10% 召回：`46.1%`；
- 建模样本：`37,222`；
- 建模特征：`204 维`；
- 历史问询案例：`4,785`；
- Agent 链路可追溯率：`100%`。

指标卡需要说明指标含义或与赛题目标的关系。实现时从项目配置、模型清单或数据产物读取；如果这些来源发生变化，页面不得继续硬编码旧数字。

### 7.3 模型图表

模型解释页保留全部已确认模块，并在正式实现时显示真实数字：

1. **30/60/90 天预测概率**：显示数值、风险阈值和窗口标签。
2. **ROC/AUC**：显示 FPR、TPR、AUC 数字、模型 ROC 曲线和随机分类基线。
3. **概率校准曲线**：显示预测概率、实际发生率、分箱点和理想校准线。
4. **混淆矩阵**：显示 TN、FP、FN、TP 的数量和占比。
5. **三模型贡献**：显示 RF、LightGBM、XGBoost 的真实权重或本次预测贡献。
6. **Top 特征贡献**：显示有符号 SHAP 值、贡献方向、特征原值和证据 ID。
7. **批量公司风险排名**：显示公司代码、预测概率、百分位、名次和 Top 10% 观察池标识。

每张图的图例直接放在图下方，例如：

- ROC：模型 ROC 曲线 / 随机分类基线；
- 校准曲线：模型实际校准 / 理想校准线；
- 混淆矩阵：预测正确 / 误报 FP / 漏报 FN；
- 风险排名：高风险优先复核 / 低风险常规观察。

正式图表优先使用 Altair 或 Streamlit 原生支持的交互图表。所有曲线应限制在固定绘图区内，采用响应式坐标系，不能通过可能导致越界的 CSS 倾斜变换绘制。

### 7.4 证据卡片与来源链接

每条证据卡包含：

- 稳定证据 ID；
- 风险等级；
- 问题类型；
- 来源名称、日期、页码或数据期间；
- 原文或原始数据片段；
- 被判定有问题的具体内容高亮；
- 问题说明；
- 相关模型特征或 SHAP 值；
- 追溯操作。

追溯操作分两层：

1. **系统内定位**：进入对应 Agent 页面并高亮指定证据。
2. **原始来源**：打开官方公告、问询函、回复文件，或显示/下载原始财务数据及计算过程。

示例证据 ID 使用 `ANN-*`、`FIN-*`、`CASE-*`。实际 ID 必须由真实数据生成，不得把视觉稿中的示例编号硬编码为正式结果。

### 7.5 Agent 执行链路

七个节点按实际执行顺序显示：信息检索、公告研读、财务检测、案例匹配、预测建模、归因分析、报告生成。每个节点显示：

- 状态；
- 耗时；
- 输出摘要；
- 使用的数据或工具；
- 错误或跳过原因；
- 展开查看完整日志的入口。

## 8. 独立 Agent 页面

### 8.1 公告研读 Agent

- 公告数量、风险要素数量、高风险证据数量和证据链接覆盖率。
- 风险类别分布、严重度分布和公告时间分布。
- 风险原文卡片，异常语句直接高亮。
- 官方公告或本地离线 PDF 的定位和下载入口。

### 8.2 财务异常 Agent

- 风险等级、异常数量、数据期和数据完整度。
- 财务指标趋势、行业偏离和异常阈值图。
- 原始值、同比/环比、行业中位数和计算公式。
- 关联公告和关联模型特征入口。

### 8.3 预测建模 Agent

- 风险概率、置信度、模型指标和三模型集成结果。
- 第 7.3 节定义的完整模型图表。
- 所有图表显示真实数字、坐标、单位、图下注释和悬停详情。

### 8.4 案例匹配 Agent

- Top-5 案例相似度、RRF 融合得分、公司、日期和问询类型。
- 区分余弦相似度与 RRF 得分，避免口径混淆。
- 展示问询关注点、原始问询函和回复要点链接。

### 8.5 归因分析 Agent

- Top 风险因素、有符号 SHAP 值、业务解释和证据 ID。
- 展示“特征 → 风险判断 → 原始证据”的关系。
- 对无法映射证据的解释进行明确警告，不伪造引用。

### 8.6 报告生成 Agent

- 使用正式研报阅读版式呈现执行摘要、预测结论、主要诱因、证据、案例和建议动作。
- 提供 Markdown、JSON 下载和历史报告索引。
- 报告中的证据引用可以返回对应 Agent 页面。

## 9. 数据流

### 9.1 离线路径

1. 页面启动。
2. 加载 `000004.SZ` 离线 Context、模型结果、报告和来源元数据。
3. 统一展示适配层将数据转换为页面 ViewModel。
4. 主控首页和各 Agent 页面立即渲染。
5. 页面标记数据为离线演示快照。

### 9.2 实时路径

1. 用户输入公司代码或公司列表并点击开始分析。
2. 主控编排器执行七 Agent Pipeline。
3. 页面实时更新节点状态和耗时。
4. 新 Context 经同一展示适配层转换为 ViewModel。
5. 当前会话显示实时结果，并允许归档和下载。

离线和实时路径必须复用同一组件与 ViewModel，防止两套页面口径漂移。

### 9.3 证据定位

证据 ID 是风险卡片、模型特征、报告引用和 Agent 页面之间的稳定关联键。用户点击证据链接时：

1. 保存目标页面与证据 ID；
2. 导航到对应 Agent 页面；
3. 页面筛选并高亮目标记录；
4. 用户可继续打开原始文件或原始数据。

## 10. 错误、慢查询与空状态

- 单个 Agent 失败不阻止其他模块展示。
- 外部数据源超时后保留离线结果，并说明哪些模块使用了快照。
- 模型冷启动期间显示当前阶段和已耗时，不显示无反馈的空白页面。
- 缺失数据展示“暂无数据”和具体原因，不显示虚构的 0 或占位数值。
- 图表数据为空时展示同尺寸空状态，避免页面跳动。
- 报告或原始文件不存在时禁用对应链接并显示缺失原因。
- 失败卡片提供重试当前环节或重新运行全部分析的入口。
- 离线、缓存和实时数据必须以清晰状态标签区分。

## 11. 展示层代码边界

建议新增独立的 `ui/` 包：

```text
ui/
├── theme.py                 # 颜色、字体、间距和全局 CSS
├── view_models.py           # Context/产物到展示数据的转换
├── offline_snapshot.py      # 离线样例和版本元数据加载
└── components/
    ├── layout.py            # 页头、区块、状态标签
    ├── metrics.py           # 对齐指标卡
    ├── charts.py            # 统一图表配置与图下注释
    ├── evidence.py          # 证据卡、问题高亮和来源链接
    ├── agent_trace.py       # 七 Agent 状态与日志
    └── states.py            # 加载、空、失败和降级状态
```

根目录七个 Streamlit 页面继续保留，改为组合共享组件。业务计算仍位于 `backend/`，展示组件不得复制模型或风险判断逻辑。

## 12. 响应式与可访问性

- 主要答辩尺寸以 1440×900 和 1280×720 为重点。
- 六列指标卡在较窄窗口下调整为三列或两列，不压缩到不可读宽度。
- 图表从双列降为单列时保持坐标、图例和数字可读。
- 所有交互元素有可见文字标签，不使用只有图标的关键操作。
- 风险等级同时使用文字和颜色。
- 正文、次要文字和状态标签满足基本对比度要求。
- 键盘焦点状态清晰，链接文字说明目标来源。

## 13. 测试与验收

### 13.1 数据与组件测试

- ViewModel 对完整、缺失和部分失败 Context 的转换。
- 指标卡数字、单位和来源映射。
- 图表输入数据长度、范围、空值和单位校验。
- 证据 ID、页面目标和原始来源链接映射。
- 离线快照元数据和报告文件完整性。

### 13.2 页面行为测试

- 首次打开无需运行即可看到完整离线样例。
- 七个页面均可通过导航入口打开并独立运行。
- 重新运行后页面由离线状态切换到实时状态。
- 单 Agent 失败、外部超时和模型不可用时正确降级。
- 报告预览和 Markdown/JSON 下载可用。
- 证据链接能够导航、筛选并高亮正确记录。

### 13.3 视觉验收

- 指标卡标题、图标、数字、单位和说明基线一致。
- 图表曲线、图例、标签和悬停区域不越出卡片。
- 模型图表包含真实数值和图下注释。
- 常见答辩窗口尺寸下无横向溢出、遮挡或不可读小字。
- 七个页面共享一致的颜色、字体、卡片、空状态和错误状态。

### 13.4 回归验收

- 改造前后相同输入得到一致的预测、归因、案例和报告数据。
- 展示层不改变模型文件、特征构建、阈值或 Agent 执行顺序。
- 现有后端测试继续通过，并增加展示适配层与关键页面测试。

## 14. 完成标准

网页展示改造在满足以下条件时视为完成：

1. 七个页面全部采用统一设计系统并保持原功能。
2. 主控首页默认展示可用的离线完整样例。
3. 所有模型图表使用真实数据，包含数字、单位和直接图下注释。
4. 证据卡片明确标出问题，并能定位原文或原始数据。
5. Agent、工具和证据来源保持 100% 可追溯。
6. 慢查询、超时、缺失数据和部分失败均有可理解的降级界面。
7. 常见答辩尺寸通过视觉检查，且核心自动测试通过。
