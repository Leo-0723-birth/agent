# 数据源与 F1 特征维度变更隐患排查报告

> 检查时间：2026-08-28  
> 检查范围：`backend/scripts/*`、`backend/agents/predictor.py`、`backend/agents/announcement_reader.py`、`backend/skills/*`、`backend/config.py`、`backend/models/predictor/models_manifest.json`  
> 当前事实：F1 数据源已从旧的 `regulatory_inquiry_semantic_*` 切换为 `announcement_semantic_*`（`raw/F1_announcement_semantic_features.parquet`），`build_modeling_dataset.py` 实际保留 Top-100，模型为树模型（RF/LGB/XGB），无神经网络显式输入层。

---

## 关键结论（TL;DR）

1. **最危险：实时路径下 F1 语义特征完全未生效**  
   `feature_composer.py` 期望的 F1 key 是 `announcement_semantic_*`，但 `announcement_reader.py` 实时输出的是 `announcement_count_*` / `risk_event_count_*` / `weighted_*` 等标量。这导致**实时扫雷与离线查表使用不同特征空间**，F1 数据源/维度变化对实时预测没有实际意义。

2. **次危险：`N_KEEP=100` 与文档/文件名“Top-50”口径不一致**  
   `processed_dataset.csv` 实际包含 100 个 `announcement_semantic_*`，而脚本注释、输出文件名、交付文档都说 Top-50。容易误导维护，也可能导致模型过度依赖 F1。

3. **第三危险：模型产物与训练数据未做版本绑定**  
   `models_manifest.json` 只存 `features` 列表，缺少 `feature_count`、`data_hash`、`generated_at` 等元信息。换源后若未完整重跑训练链路，`PredictorAgent` 会静默加载旧模型/旧清单，造成预测错误。

4. **整体评估**：当前离线查表路径基本可用，但实时路径与离线路径的特征空间已经分裂；多个硬编码阈值、列名、窗口、 split 取值在数据源变更后都会成为“静默错误”来源。

### P0（必须立即修复，否则实时/离线特征空间分裂）

## 8. 推荐的完整重跑流程

若已确认新 F1 数据源可用，建议按以下顺序重跑，确保线上线下一致：

1. 更新 `backend/config.py` 中的 F1 路径/前缀/Top-K 配置。
2. 重新运行 `rebuild_f1_from_fullrun.py`（若需要重新生成公告语义特征）。
3. 重新运行 `build_modeling_dataset.py` 生成 `processed_dataset.csv`。
4. 重新运行 `train_models.py` 训练模型并更新 `models_manifest.json`。
5. 在 `PredictorAgent` 启动脚本中增加 manifest/数据集/fill 一致性校验。
6. 选择并实施实时 F1 对齐方案（2.3），然后做实时扫雷回归测试。
