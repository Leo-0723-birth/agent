# 典型案例分析报告：000004.SZ

## 案例定位

- 公司：000004.SZ
- 预测窗口：60 天
- 建议展示日期：运行时填写 `as_of`
- 运行入口：`streamlit run 导航入口.py` 或 API `POST /predict`

## 分析内容

系统依次完成公告研读、财务异常检测、问询概率预测、相似案例检索、chunk 证据召回和归因报告生成。预测页展示 30/60/90 天概率；归因页展示 SHAP/规则诱因、原文证据 ID 和 Top-5 相似案例；报告页展示完整 Markdown/JSON 与 trace。

## 复现命令

```powershell
.\.venv\Scripts\python.exe 官方要求交付物\batch_predict.py --companies 000004.SZ
```

运行后，将生成的 JSONL 和 Reporter 自动归档的 Markdown 报告一起作为本案例的证据附件。报告只引用原文证据白名单，不把模型叙述当作事实来源。

## 解读边界

该案例用于展示端到端可解释链路，不代表对单家公司作投资判断；概率是方向性预警信号，最终结论应结合最新公告和人工复核。

## 评委现场观察清单

| 观察项 | 应看到的结果 |
|---|---|
| 预测 | 30/60/90 天概率、风险等级、置信度、数据源 |
| 归因 | Top 风险因素、SHAP 方向或规则降级标识 |
| 证据 | 每个可验证诱因对应 evidence_id 和原文片段 |
| 案例 | Top-5 历史问询案例及相似度/关注点 |
| 追踪 | 7 个 Agent 的 run_id、状态和耗时 |
| 报告 | 同一结果的 Markdown 与结构化 JSON |

若在线数据源不可用，页面应展示降级状态和原因；降级不应被表述为实时数据，也不应从最终报告中隐藏。
